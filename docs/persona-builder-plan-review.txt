Are there model inputs the builder can't control but should (e.g. category mix, popularity, recency)? Does anything the plan adds have no effect on the model? 3. Generator design. Is the algorithm deterministic as described? Do the quota and greedy-score steps produce the claimed results, including when the catalog runs out? 5. Presets and caching. Do the proposed presets give visibly different model output, given the catalog limits? Does the snapshot test plus basketKey approach actually protect cached model/LLM output from going stale?

6. Interfaces with other steps. Is the ScoreRequest shape reasonable for the backend's existing event pipeline (units_from_events / build_docs)? Does anything conflict with the layout plan (e.g. home.basketIds, the validator, PersonaPanel ownership)? Is the work order safe to run alongside step 1?
