# Backend — SOCAL ATELIER / Refit models

Training and serving code for the two personalization models, ported from the
`model` branch of `AnselZeng/la-hacks` (working tree, including the 2019
reserved-window test work). Frontend v1 uses heuristic personas — the store is
not blocked on Python.

| Folder | What it is |
| --- | --- |
| `model/` | H&M homepage model: history features, LightGBM layout models, LambdaRank item ranker, homepage export, Supabase publish, the reserved 2019 test (`test2019.py`, `windows.py`, `results/`, `REVIEW_RESPONSE.md`) |
| `session_model/` | OTTO live-session model (clicks/carts/orders → browsing style → UI decisions) |
| `server/` | Serving layer: `bundle.py`, `score.py`, `retrain.py`, `refresh.py`, `simulate.py`, Snowflake helpers, `schema.sql`, and a Next.js API layer under `server/app/` (`/api/layout`, `/api/events`) |
| `src/` | `atelier_data` package: dataset pipeline, fusion, evaluation (install with `pip install -e .`) |
| `tests/`, `config/`, `config_generated/` | Pipeline tests and configs |
| `docs/` | Dataset docs (`DATASET.md`, `README-model-branch.md`) |
| `supabase/` | Schema and publish helpers |
| `reports/` | Dataset-v1 build reports |

Docs: `FUSION.md` (H&M+OTTO fused dataset), `Context.MD`, `model/README.md`,
`session_model/README.md`, `server/README.md`.

## Setup

```bat
cd backend
python -m venv .venv && .venv\Scripts\activate
pip install -e . -r requirements.txt
copy .env.example .env   :: fill in Supabase keys; never commit .env
```

## Not in this repo

- `data/` (H&M + OTTO raw/processed data) — licensed/private, pull from Supabase
  (`python -m atelier_data.cloud download`) or Git LFS on the la-hacks `dataset` branch.
- `model/work/`, `session_model/work/`, `server/work/` — local run artifacts
  (parquet/pickle intermediates), regenerated by the pipelines.
- `artifacts/frontend/shoppers.json` and other H&M-derived shopper files —
  keep them out of public repos per the H&M competition rules.
